# RITES × Carbon Actual Conformance

RITES remains a standalone human-continuity product. It inherits shared Carbon Actual identity, authority, ABBA, event/Pulse, provenance, security, value and data-lifecycle capabilities rather than recreating them.

## Shared inheritance

RITES uses the ecosystem contracts for human/entity identity, `#` lineage, relationships, consent, delegated authority, Seal, Pulse/events, provenance, Vault, value, audit, security and Ash/Phoenix recovery.

## RITES-owned experience

The product retains its own ROOT, LIFE, STEWARD, RITE, CONTINUUM and TRANSITION ENGINE experience, including wishes, cemetery/provider coordination, digital estate, legacy and continuity workflows.

## Boundary rule

RITES must not create a competing canonical identity, authority, Pulse, provenance or security ontology. Product-specific extensions must remain interoperable with the canonical contracts.
